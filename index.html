    How each projection works
    Burn-up or burn-down
    A burn-up plots completed work against total scope as separate lines, so added work stays visible. A burn-down plots only remaining work, which is simplest to read when scope is fixed. The page picks one automatically: if more than 15% of the final scope was added or removed after the release started, it shows the burn-up; otherwise the burn-down. Use the toggle to switch. On the burn-down, triangles mark days when tickets were added, so those upward jumps aren't mistaken for the team slowing down.
    Linear regression
    A least-squares straight line through cumulative completed work for each day in the fit window. Its slope is projected forward from the actual completed work on the as-of date until it reaches today's total scope. The faint line on the burn-up shows the fit itself.
    Linear + scope growth
    Also fits a line to total scope over time. Remaining work shrinks by the completion rate minus the scope-growth rate. This is the realistic date if tickets keep being added at the same rate.
    Polynomial regression
    A quadratic or cubic least-squares curve through the same points, continued from the actual as-of value. It captures acceleration or slowdown, but it can swing a lot on little data. If the curve flattens before reaching scope, there is no date.
    Average velocity
    Remaining work ÷ the mean amount completed per full week in the fit window.
    Optimistic / pessimistic bounds
    Optimistic: every remaining ticket is one Fibonacci step smaller than its estimate (5 → 3), delivered at the fastest rolling-average velocity seen. Pessimistic: one step larger (5 → 8), at the slowest non-zero rolling velocity. For Original estimate, the ± uncertainty percentage is used instead of Fibonacci steps.
    Ticket rate
    Open tickets ÷ the mean number of tickets completed per week. This ignores estimates entirely, which makes it a useful cross-check.
    Monte Carlo
    Picks random past full weeks (with replacement) and plays them forward until remaining work hits zero, 5,000 times. P50 means half of the simulated futures finished by that date; P85 is a common commitment date. With “Randomise ticket sizes”, each open ticket's size is drawn from its optimistic, estimated or pessimistic size (25% / 50% / 25%) in every run. With “Keep adding scope”, each replayed week also adds the scope that was added in that same historical week.
    Assignee bottleneck
    The latest per-person finish date, assuming nobody picks up anyone else's tickets. Unassigned tickets are listed but not projected.
    Backtesting
    Set “As of” to a past date to see what the app would have predicted then. Tickets created after that date are ignored, and tickets resolved after it count as still open. Compare the result with what actually happened.
    Caveats
    In-progress tickets count as fully remaining. Tickets created before the release start count as initial scope. Weekly figures use calendar weeks starting on Monday, so holidays and time off show up as slow weeks.
